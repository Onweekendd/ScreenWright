# 原子组件迁移方案：文字 / 图片 / 矩形 / 通用图表

> 状态：**方案稿，待评审**。带 `TBD` 的地方是有意留空的，评审时定。
> 相关：`docs/生图到大屏工作流.md`（AI 链路的主要使用方）、`.claude/skills/sw-add-component`（新增组件的注册步骤）。

---

## 0. 一句话

**文字 `swtext` 和图片 `swimg` 原地换成新 schema**：prop 名不变，配置项改成 CSS 写法，旧数据在读取时自动升级。另外新增矩形 `swBox`，升级通用图表 `echartcommon`。大部分大屏只用这 4 个组件就能搭出来。

---

## 1. 为什么要做

现有组件的 schema 是按"给人在属性面板里点选"设计的：每个面板控件对应一个扁平字段，渲染时再把这些字段翻译成 CSS 或 ECharts 配置。人用起来没问题，但现在多了一个使用方，就是 AI 链路（生图到大屏、校准修正、对话改组件），这套设计对 AI 很不友好。

| 问题 | 例子 | 对 AI 的影响 |
|---|---|---|
| 私有命名 | 字间距叫 `split`，阴影模糊叫 `shadowFuzzy`，`xAxisSplitLineColor` 对应 `xAxis.splitLine.lineStyle.color` | 模型没见过这些名字，每次都得先读 skill 文档 |
| 字段量大且不统一 | 33 个图表 schema 每个 117~198 个字段，去重后 556 个字段名，只有 18 个在 20 个以上的图表里通用 | 每个组件都要单独学；skill 文档总共约 380KB |
| 一个概念拆成多个字段 | 阴影 5 个字段；颜色是"渐变对象 + picker 字符串"成对存储；滤镜是"开关 + 数值"成对 | 模型经常只改对一半 |
| 同一个值存两处 | swimg 的地址同时在 `data[0].value` 和 `option.url` | 模型写错一处，组件就不显示 |
| 缺字段时默认值危险 | `fontSize: option.xAxisFontSize \|\| 0`，swimgBorder `opacity \|\| 0` | 漏写一个字段，字号就变成 0，或者组件直接透明 |
| schema 和实现不一致 | swText 实际读了 `isLineHeight`、`scroll`、`speed`、`step`、`textAnimation*`、`rotateShow`、`clickFormatter`，但 schema 里都没有 | 模型照着 schema 写，写了也不生效；想要的效果 schema 里又找不到 |

参照：乐吾乐 meta2d 的模板中，117 个图元里 text、image、square 占 103 个（88%），图表直接存原生 ECharts option，字段名基本都是 CSS / Canvas 原生命名。

---

## 2. 设计原则

1. **内容写 data，样式写 option**。这是平台现有的约定，继续沿用：文字内容和图片地址都放在 `data[0].value`，这里是**唯一**的来源。行内编辑（`useFtTextEdit`）、状态动画（`mappings.ts`）、数据源、figma 转换写的都是 data，这些都不用改。option 里不再重复存一份。
2. **样式使用 CSS 词汇**。字段名和取值都直接用 CSS（`fontSize`、`letterSpacing`、`textShadow: "0 0 8px #4583ff"`），图表直接存 ECharts option。
3. **所有字段都可选，默认值由渲染层给出且安全**。option 为空时也必须能正确渲染（白字、14px、默认字体）。禁止用 `|| 0` 这种会让漏写字段变成 0 的写法。
4. **每个概念只存一处**。复合属性（阴影、渐变、滤镜、边框、变换、动画）存成完整的 CSS 字符串，不拆开。
5. **schema 就是真相**。渲染层只读 schema 里声明过的字段；schema 使用 `.strict()`。
6. **面板只是存储的一个视图**。面板控件通过 `path` 读写 option（§6）。
7. **只管组件自身**。位置和尺寸、显隐、事件、进场动画、数据源，继续使用 ComponentSchema 的公共字段。

---

## 3. 范围

| 组件 | prop | 做法 | 覆盖的场景 |
|---|---|---|---|
| 文字 | `swtext` | **原地替换** schema 和渲染 | 标题、指标数值、单位、标签、跑马灯、超链接 |
| 图片 | `swimg` | **原地替换**；`swimgBorder` 合并进来 | 卡片框、标题条、装饰、设备图标、底图、旋转/呼吸动画 |
| 矩形 | `swBox`（新增，TBD 命名） | 新增 | 蒙层、渐变块、分隔区、发光边框、毛玻璃底板 |
| 通用图表 | `echartcommon` | 增加 JSON 主通道，旧数据兼容 | 所有 ECharts 能画的图 |

**不在范围内**：状态文本 swText2、富文本、多行文本、轮播、视频、表格、3D 和地图；33 个私有图表组件保持不动（AI 链路改用 echartcommon）。

### 为什么选择原地替换、而且不改 prop 名

prop 名 `swtext` / `swimg` 在 30 多处代码里被引用，包括：事件和行为白名单、`pointerEventsComponent` 列表、双击行内编辑、状态动画映射、`create-component` 工具、figma 转换策略、`extract-slots` 脚本、SDK 类型声明（`hooks.d.ts`），以及桌面端打包进去的 server。事件里引用组件用的是 id，不涉及 prop。
所以 **prop 不变，只换 option 的结构**，影响范围就收敛为"读写 option 字段的地方"，§8.3 逐一列出了这些位置。

## 4. 组件规格

### 4.1 文字 swtext（v2）

```ts
// packages/types/src/schemas/components/text/swtext.ts（替换）
import { z } from "zod";

/**
 * 文字 (swtext) v2
 * 文字
 *
 * 字段名与取值与 CSS 保持一致。所有字段可选，缺省走渲染层默认值。
 *
 * ## 数据结构
 * - `value` - 文字内容（唯一来源；静态文字和数据源绑定都写这里）
 *
 * @example
 * ```typescript
 * const data: SwTextData = [{ value: "暖通可视化系统" }];
 * ```
 */
const swTextDataItemSchema = z.object({
  value: z.union([z.string(), z.number()]).describe("文字内容")
});
export const swTextDataSchema = z.array(swTextDataItemSchema);
export type SwTextData = z.infer<typeof swTextDataSchema>;

export const swTextOptionSchema = z
  .object({
    // ============ 字体 ============
    fontFamily: z.string().describe("CSS font-family").optional(),
    fontSize: z.number().describe("字号(px)").optional(),
    fontWeight: z.union([z.number(), z.string()]).describe("CSS font-weight，如 400 / 'bold'").optional(),
    fontStyle: z.enum(["normal", "italic"]).optional(),
    letterSpacing: z.number().describe("字间距(px)").optional(),
    lineHeight: z.number().describe("行高，CSS 无单位倍数，如 1.5").optional(),

    // ============ 颜色与效果 ============
    color: z
      .string()
      .describe("纯色 '#fff' / 'rgba(...)'，或 CSS 渐变 'linear-gradient(90deg,#fff,#496adc)'；多层渐变用逗号分隔")
      .optional(),
    textShadow: z.string().describe("CSS text-shadow，发光如 '0 0 24px rgba(69,131,255,1)'；可多层").optional(),
    background: z.string().describe("文字底色，CSS background").optional(),
    opacity: z.number().min(0).max(1).optional(),

    // ============ 排版 ============
    textAlign: z.enum(["left", "center", "right"]).optional(),
    verticalAlign: z.enum(["top", "middle", "bottom"]).describe("在组件框内的垂直位置").optional(),
    whiteSpace: z.enum(["nowrap", "normal", "pre-line"]).describe("nowrap 单行 / normal 自动换行 / pre-line 保留换行符").optional(),
    textOverflow: z.enum(["clip", "ellipsis"]).optional(),
    writingMode: z.enum(["horizontal-tb", "vertical-rl", "vertical-lr"]).optional(),
    textOrientation: z.enum(["mixed", "upright"]).optional(),

    // ============ 变换与动画 ============
    transform: z.string().describe("CSS transform，如 'rotateZ(15deg)'").optional(),
    animation: z.string().describe("CSS animation 简写，关键帧名取内置预设（§5.3），如 'sw-breath 2s ease-in-out infinite'").optional(),

    // ============ 数值格式化 ============
    template: z.string().describe("显示模板，{value} 替换为内容，如 '{value} kWh'；不填直接显示内容").optional(),
    decimals: z.number().int().min(0).describe("内容为数字时保留的小数位").optional(),
    thousands: z.boolean().describe("内容为数字时显示千分位").optional(),

    // ============ 跑马灯 ============
    marquee: z
      .object({
        speed: z.number().describe("滚动速度(px/s)"),
        direction: z.enum(["left", "right"]).optional()
      })
      .describe("有此字段即为跑马灯")
      .optional(),

    // ============ 超链接 ============
    href: z.string().describe("有此字段即为超链接").optional(),
    target: z.enum(["_self", "_blank"]).optional(),

    // ============ 交互 ============
    pointerEvents: z.boolean().describe("是否响应鼠标，默认 false").optional()
  })
  .strict();

export type SwTextOption = z.infer<typeof swTextOptionSchema>;
```

**默认值**（渲染层集中定义一份 `DEFAULTS` 常量）：

| 字段 | 默认值 |
|---|---|
| `fontFamily` | `"Source Han Sans CN"`（沿用现在的值） |
| `fontSize` | `14` |
| `fontWeight` | `400` |
| `color` | `"#ffffff"` |
| `lineHeight` | `1.2` |
| `textAlign` | `"left"` |
| `verticalAlign` | `"middle"` |
| `whiteSpace` | `"nowrap"` |
| `textOverflow` | `"ellipsis"` |

**渲染要点：**

- **渐变文字**：`color` 以 `linear-gradient` / `radial-gradient` 开头时，改用 `background-image` + `background-clip: text` + `-webkit-text-fill-color: transparent` 渲染。多层渐变直接作为多个 `background-image` 叠加（取代旧的 multiGradient 图层数组）。
- **渐变文字和阴影冲突**：`background-clip: text` 下 `text-shadow` 会盖在渐变上面，所以这种情况下渲染层把 `textShadow` 转成 `filter: drop-shadow(...)`（现在的 swText 就是这么处理的）。schema 始终只有 `textShadow` 一个字段。
- **跑马灯、超链接、普通文字**由字段是否存在来区分，不再用 `type` 枚举，也不再按组件 `title`（文本框 / 跑马灯 / 超链接）去切换面板。
- 物料面板里"文本框 / 跑马灯 / 超链接"三个入口保留，区别只是初始 option 不同（modules 表 63/64/65）。

### 4.2 图片 swimg（v2，合并 swimgBorder）

```ts
// packages/types/src/schemas/components/media/swimg.ts（替换）
import { z } from "zod";

/**
 * 图片 (swimg) v2
 * 媒体
 *
 * ## 数据结构
 * - `value` - 图片地址（唯一来源；不再写 option.url）
 */
const swimgDataItemSchema = z.object({
  value: z.string().describe("图片地址")
});
export const swimgDataSchema = z.array(swimgDataItemSchema);
export type SwimgData = z.infer<typeof swimgDataSchema>;

export const swimgOptionSchema = z
  .object({
    objectFit: z.enum(["fill", "contain", "cover"]).describe("CSS object-fit，默认 fill").optional(),

    // ============ 九宫格（原 swimgBorder）============
    slice: z
      .tuple([z.number(), z.number(), z.number(), z.number()])
      .describe("上右下左四边不拉伸的宽度(按原图像素)，对应 CSS border-image-slice；给了就按九宫格渲染")
      .optional(),
    sliceScale: z.number().describe("九宫格边宽在画布上的缩放倍数，@2x 素材填 0.5；默认 1").optional(),

    // ============ 外观 ============
    background: z.string().describe("图片下方的底色，CSS background").optional(),
    opacity: z.number().min(0).max(1).optional(),
    borderRadius: z.number().describe("圆角(px)").optional(),
    filter: z.string().describe("CSS filter，如 'blur(4px) brightness(1.2) grayscale(1)'").optional(),
    mixBlendMode: z.string().describe("CSS mix-blend-mode，如 'screen'").optional(),

    // ============ 变换与动画 ============
    transform: z.string().describe("CSS transform，如 'scaleX(-1)' 水平翻转、'rotateY(30deg)'").optional(),
    animation: z.string().describe("CSS animation 简写，关键帧名取内置预设（§5.3），如 'sw-rotate 8s linear infinite'").optional(),
    keyframes: z
      .array(z.record(z.string(), z.union([z.string(), z.number()])))
      .describe("自定义关键帧（Web Animations API 格式），如 [{transform:'translateY(0)'},{transform:'translateY(-10px)'}]；有此字段时 animation 只取时长/缓动/次数")
      .optional(),
    transition: z.string().describe("换图时的过渡，CSS transition，如 'opacity 300ms'").optional(),

    // ============ 交互 ============
    pointerEvents: z.boolean().describe("是否响应鼠标，默认 false（装饰图不挡交互）").optional()
  })
  .strict();

export type SwimgOption = z.infer<typeof swimgOptionSchema>;
```

**渲染要点：**

- 有 `slice` 时，按九宫格渲染：`border-image-source: url(src)`，`border-image-slice: t r b l fill`，`border-width` 为 slice × sliceScale，`border-style: solid`。**一定要加 `fill`**，否则中间区域是空的。
- 没有 `slice` 时，用 `<img>` 加 `object-fit`。
- 图片地址统一经过 `setMinioUrl` 处理。
- 旧的 `cover`（封面图）字段：TBD。先确认它现在是否还有实际用途，没有就不迁移。

### 4.3 矩形 swBox（新增）

```ts
// packages/types/src/schemas/components/media/swBox.ts
import { z } from "zod";

/**
 * 矩形 (swBox)
 * 媒体
 *
 * 纯 CSS 盒子，用于蒙层、渐变块、分隔区、发光边框、毛玻璃底板。无数据。
 */
export const swBoxDataSchema = z.array(z.unknown()).max(0);

export const swBoxOptionSchema = z
  .object({
    background: z.string().describe("CSS background，可为渐变").optional(),
    border: z.string().describe("CSS border，如 '1px solid rgba(69,131,255,.4)'").optional(),
    borderRadius: z.union([z.number(), z.string()]).describe("圆角，数字为 px；字符串按 CSS，如 '8px 8px 0 0'").optional(),
    boxShadow: z.string().describe("CSS box-shadow，内发光如 'inset 0 0 20px rgba(69,131,255,.5)'").optional(),
    backdropFilter: z.string().describe("毛玻璃，如 'blur(8px)'").optional(),
    opacity: z.number().min(0).max(1).optional(),
    clipPath: z.string().describe("CSS clip-path，切角/斜边，如 'polygon(12px 0,100% 0,100% 100%,0 100%,0 12px)'").optional(),
    transform: z.string().optional(),
    animation: z.string().describe("CSS animation 简写，关键帧名取内置预设（§5.3）").optional(),
    pointerEvents: z.boolean().describe("是否响应鼠标，默认 false").optional()
  })
  .strict();
```

默认值全部为空，也就是一个透明的盒子。渲染层直接把这些 option 展开到 div 的 style 上。

### 4.4 通用图表 echartcommon（升级）

现在只有一个 `echartFormatter` 字段：一段 JS 函数字符串，运行时执行 `(dataChart) => option`（见 `apps/app/src/components/ScreenwrightThirdPartComponent/echartcommon/useEchartsCommon.ts`）。存在的问题：

- 代码没法按路径局部修改。
- 没法用 zod 校验。
- 代码没法统一注入主题色。
- AI 生成的内容会被直接 eval。

升级方案：**新增 JSON 主通道，函数降级为兜底**。旧数据兼容。

```ts
// packages/types/src/schemas/components/third-party/echartcommon.ts（升级）
export const echartcommonOptionSchema = z
  .object({
    echartsOption: z
      .record(z.string(), z.unknown())
      .describe("原生 ECharts option，不含数据；数据由 dataset.source 注入，series 用 encode 引用列")
      .optional(),
    echartFormatter: z
      .string()
      .describe("可选。(data, option) => option；在 echartsOption 基础上再加工，仅在 JSON 表达不了时使用")
      .optional()
  })
  .strict();

/** 有 echartsOption 时：dataChart 就是一张二维表（对象数组），直接作为 dataset.source */
export const echartcommonDatasetSchema = z.array(z.record(z.string(), z.union([z.string(), z.number(), z.null()])));
```

**数据约定**：使用 ECharts 原生的 `dataset` + `encode`。

```jsonc
// data（dataChart）
[
  { "name": "1月", "本月": 5.2, "上月": 4.8 },
  { "name": "2月", "本月": 5.6, "上月": 5.1 }
]
// option.echartsOption
{
  "color": ["#4DF1FE", "#4583FF"],
  "grid": { "left": 8, "right": 8, "top": 30, "bottom": 20, "containLabel": true },
  "xAxis": { "type": "category", "axisLabel": { "color": "#B3D1FF", "fontSize": 12 } },
  "yAxis": { "type": "value", "splitLine": { "lineStyle": { "color": "rgba(255,255,255,.08)" } } },
  "series": [
    { "type": "bar", "encode": { "x": "name", "y": "本月" }, "barWidth": 8 },
    { "type": "line", "encode": { "x": "name", "y": "上月" }, "smooth": true }
  ]
}
```

**渲染流程**：

```
有 echartsOption：
  option = deepClone(echartsOption)
  option.dataset = { source: dataChart }            // 覆盖，不合并
  if echartFormatter: option = formatter(dataChart, option)
  setOption(option, { notMerge: true })
没有 echartsOption（旧数据）：
  走现有逻辑：echartFormatter(dataChart) → option
```

**要点：**

- **JSON 里不能写函数**。标签格式化优先用 ECharts 的字符串模板（`formatter: "{b}: {c} kWh"`），确实需要函数时才用 `echartFormatter`。
- **主题注入**：顶层 `color` 数组就是 ECharts 原生的调色板，代码注入主题色只需要改这一处。
- **文字外置**（推荐写法，不强制）：需要像素级对齐的坐标轴标签和数值，可以设为 `show: false`，改用独立的 swtext 摆放。
- **安全**：AI 链路默认不生成 `echartFormatter`；TBD：是否加白名单或沙箱。

## 5. 公共约定

### 5.1 字段名与取值

| 规则 | 说明 |
|---|---|
| 字段名 | 等于 CSS 属性的 camelCase 写法，不加前后缀，不缩写。超链接用 HTML 属性名 `href` / `target` |
| 纯数字 | 统一按 px 处理，渲染层补单位；`lineHeight`、`opacity` 例外 |
| 颜色 | CSS 颜色字符串或 CSS 渐变字符串；不再使用 `{type, angle, colors}` 这样的渐变对象 |
| 复合属性 | 存成完整的 CSS 字符串：`textShadow`、`boxShadow`、`border`、`filter`、`transform`、`animation`、`clipPath` |
| 开关 | 不使用"xxxShow + xxx"成对的字段；不写就等于关闭 |
| 枚举值 | 直接用 CSS 的关键字 |

### 5.2 默认值

- 每个组件在渲染层维护一份 `DEFAULTS`，渲染时 `{ ...DEFAULTS, ...option }`。
- 默认值必须能在深色大屏上直接使用。
- **禁止** `option.x || 0`、`option.x || "#333"` 这类写法。

### 5.3 内置动画关键帧

`animation` 字段使用 CSS 简写，关键帧名取下面这组全局预设（在 material 的全局样式里定义一次）。旧 swimg 渲染时本来就是拼成 `${animationType} ${time}s ${speed} 0s` 这样的 CSS 简写，这里只是把关键帧名规范化：

| 关键帧名 | 效果 | 对应旧 swimg `animationType` |
|---|---|---|
| `sw-rotate` | 顺时针旋转 | `clockwise` |
| `sw-rotate-reverse` | 逆时针旋转 | `counterclockwise` |
| `sw-breath` | 透明度呼吸 | `opacity` |
| `sw-zoom` | 缩放脉冲 | `zoom` |
| `sw-float` | 上下浮动 | `upOrDown` |
| `sw-swing` | 左右摆动 | `backAndForth` |
| （自定义） | `keyframes` 字段 | `customize` |

旧 swtext 的 `textAnimationType`：TBD，确认它有哪几种取值后，并入这张表。

### 5.4 什么不放进 option

位置和尺寸、层级、显隐、锁定、事件联动、进场动画（`loadAnimation`）、数据源配置，继续使用 ComponentSchema 的公共字段。

## 6. 属性面板：按 path 描述，自动生成

swtext、swimg 的旧面板**整体替换**。新组件的面板不再为每个组件手写 Vue 文件，而是每个组件写一份面板描述，由通用渲染器生成。

```ts
// packages/material/src/editor-ui/atomic/panelField.ts
export interface PanelField {
  path: string;        // 相对组件的路径，lodash get/set，如 "option.textShadow"、"data[0].value"
  label: string;
  group: string;
  control:
    | "text" | "textarea" | "number" | "switch" | "select"
    | "color"            // 纯色 + 渐变 + 多层渐变，读写 CSS 颜色字符串
    | "font"
    | "shadow"           // 读写 CSS text-shadow / box-shadow 字符串
    | "border" | "filter" | "transform"
    | "animation"        // 预设关键帧 + 时长 + 缓动 + 次数，读写 CSS animation 字符串
    | "slice"            // 在图片上拖 4 条参考线
    | "image"
    | "json";            // echartsOption 高级编辑（Monaco）
  options?: { label: string; value: string | number }[];
  unit?: string;
  min?: number;
  max?: number;
  /** 仅当条件成立时显示，如跑马灯速度只在 option.marquee 存在时显示 */
  visibleWhen?: string;
}
```

## 8. 迁移：读取时自动升级

### 8.1 机制

旧格式的数据会长期存在：用户本地的数据库（桌面端每台机器一份）、导出的大屏 JSON、模板、图层收藏（`layers` 表）、物料模板（`modules` 表）。所以**不能只靠一次性脚本迁移**，需要一个**在读取时自动升级**的纯函数：

```ts
// packages/types/src/migrations/atomic.ts —— 前后端共用，纯函数、幂等
export function upgradeComponent(c: ComponentType): ComponentType {
  switch (c.component.prop) {
    case "swtext":      return isV2(c) ? c : upgradeSwText(c);
    case "swimg":       return isV2(c) ? c : upgradeSwImg(c);
    case "swimgBorder": return upgradeSwImgBorder(c);   // prop 改为 swimg
    default:            return c;
  }
}
```

**在哪里调用**（所有"把组件读进内存"的入口）：

- 前端加载大屏版本、预览、发布页；
- 导入大屏或模板 JSON、从图层收藏中插入；
- 服务端 agent 工具读取大屏时（组件查询类工具、`extract-slots`）；
- 递归处理子组件（分组 `children`、动态面板 `panelData`、`presetChild`）。

**保存时一律写 v2**。modules 表中 43 / 44 / 63 / 64 / 65 这几条物料模板，用 prisma 迁移直接改成 v2。

**如何判断是不是 v2**（TBD，二选一）：
- A：在 `component` 上加 `schemaVersion: 2`（推荐：判断明确，而且 option 保持纯 CSS）；
- B：检测 option 里有没有旧字段（`split`、`selectedTextType`、`shadowShow` 等）。实现简单，但边界情况容易误判。

**向下兼容**：v2 数据在旧版客户端上无法正确显示。桌面端需要在"导入 / 打开"时检查版本，提示用户升级客户端（TBD）。
