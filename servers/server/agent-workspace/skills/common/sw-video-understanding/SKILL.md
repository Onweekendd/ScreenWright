# 视频理解与创作

目标是建立有时间依据的镜头理解，再据此创作。视频 URL、文件名、搜索标题和生成工具的成功结果都不代表已经看过内容。

## 获取与观看

1. 将用户上传或搜索得到的视频下载到当前工作区的 `screen_<id>_<version>/assets/` 下，为源视频、抽帧和拼图使用独立目录，保留源文件。使用真实返回的 URL；签名 URL 原样引用并检查有效期，下载后确认得到的是可解码视频而非错误页。已有本地文件可直接使用。
2. 用 `ffprobe` 记录时长、分辨率、画幅、帧率、旋转信息、是否有音轨；变帧率视频以实际呈现时间戳为准。缺少工具或下载失败时说明具体阻塞，不能编造视频分析。
3. 默认**每隔 10 帧取一张**，允许在 8–12 帧之间调整。这是源视频帧间隔，不是每秒 8–12 张，也不是整段只取 8–12 张。例如恒定 30 fps 时，每 10 帧约为 0.33 秒；不要先改帧率再声称间隔对应原视频帧。
4. 按时间顺序拼图，**从左到右、从上到下**。建议每页 4–6 列、最多 24 张，缩略图保持比例、不裁切主体，短边约 240–360 像素。每格标注帧编号和源视频时间戳；无法绘字时提供明确的格子到时间戳的索引文件。长视频按时间窗口分页，保留窗口起点，不能将局部时间误当成全片时间。
5. 用 `read_file`（前端工具名 `readFileTool`）逐页读取拼图，让图片通过现有中间件进入视觉上下文。**生成了拼图不等于看过拼图**；页面缩放后细节不清晰，就减少每页格数，或另读原始帧。
6. 初步识别切镜、动作变化和疑点，再对这些区间加密抽帧，必要时逐帧核对。8–12 帧间隔可能漏掉闪切、文字和短动作，不足以证明精确剪辑点或运动轨迹。

命令与时间戳处理见 [references/frame-analysis.md](references/frame-analysis.md)，实际执行前只需读取这一份参考。

## 提取哪些信息

先给全片概要（内容、镜头顺序、总体风格、叙事目的），再按镜头记录下列信息。简单问题只输出相关字段，完整分析可写入 `assets/<视频名>/analysis.md`，不要把所有帧的描述塞进聊天。

| 信息 | 需要观察的证据及用途 |
| --- | --- |
| 时间与剪辑 | 镜头起止时间、时长、硬切/叠化等转场；抽帧估算的边界注明误差或待精查。用于分镜和节奏复现。 |
| 场景与主体 | 地点类型、人物/动物/物体、主体数量、发生的动作、动作先后；地名和身份无法确认时不作断言。 |
| 构图与空间 | 景别、视角、主体位置、前中后景、地平线、遮挡关系、可用留白。用于参考图选择和画幅适配。 |
| 相机运动 | 固定、水平摇摄、俯仰、横移、推近/拉远、升降、环绕、跟拍；写方向、幅度、快慢、加减速及判断依据。 |
| 主体与环境运动 | 主体相对背景的运动方向和速度，水流、云、树叶等独立变化；与相机运动分开记录。 |
| 视觉风格 | 主色、饱和度、明暗对比、光线方向、天气、景深、质感、稳定程度；用于生成时保持一致。 |
| 连续性锚点 | 可跨帧追踪的树、山峰、建筑、地平线、主体轮廓，以及首尾帧位置和尺度；用于运动判断、接片和查跳变。 |
| 声音与文字 | 可见字幕、标识及其时间范围；声音只在实际听取/转写后描述。静态拼图无法判断配乐、台词或音画同步。 |
| 创作可用性 | 哪段满足用户目标、哪些片段应保留、续接点、可作首尾帧的清晰画面、需避免的穿帮或遮挡。 |

### 如何可靠判断运动方向

- 对比同一镜头的前、中、后帧，追踪至少两个不同深度的静态锚点，先描述**画面中的位移**，再推断相机运动。比如“背景整体向左”可能支持相机向右摇摄，但不能把画面方向直接写成相机方向。
- 区分摇摄与横移：横移通常带来近远景不同的位移、遮挡和视差变化；证据不足时写“向右摇摄或横移，无法区分”，不要强判。
- 区分推拉、变焦与主体移动：推拉会改变视差与空间关系，变焦主要改变整体尺度；仅凭物体变大不能确认相机前进。单个主体移动而背景稳定时，优先考虑主体自身运动。
- 不要只看远山或天空。远景移动很小，相机仍可能在动；同时检查近景边缘、地面纹理、遮挡和地平线。画面几乎不变时可写“固定或运动极轻微”，不可无依据断言绝对固定。
- 每项结论写成“方向/类型 + 证据时间点 + 置信度”。切镜、叠化、手持抖动、电子防抖、裁切都可能干扰判断，疑点用更密的帧复核。

## 将理解用于创作

围绕用户明确的成片目标决定保留、改编、续接或新生成的部分，不强迫用户指定执行步骤。区分原始片段与 AI 生成片段；用户要求“前 10 秒使用找到的视频”时，把这一点作为实际剪辑约束，不能用生成内容冒充。

1. **形成分镜意图**：每段写清时长、主体/场景、构图、主体动作、相机运动、光色及接入/接出方式。复杂目标按镜头生成，避免把多个互相冲突的运镜塞进一个短镜头。
2. **选择生成条件**：先查看 `createVideoTool` 当前参数与限制。文生视频描述场景和运动；首帧图生视频用画面作外观依据，提示词集中写运动和保持项；首尾帧模式控制接续；多模态参考模式按工具支持传入参考素材。首尾帧不能与多模态参考参数混用。
3. **准备可访问素材**：图片参考使用工具要求的内部 assetStore URL；参考视频/音频使用服务商可下载的 URL。工作区路径和服务端 `127.0.0.1` 地址不能直接当作外部生成服务能访问的素材。不要把拼图当成首帧，否则可能生成网格画面；应选取单张原始帧。拼图仅用于分析。
4. **写提示词**：用“场景/主体（文生时）→主体动作→相机类型、方向、速度→光色风格→需保持的构图/外观→必要约束”组织。把“高级、有氛围、动起来”换成可观察动作，如“镜头缓慢向后拉远，近景花海逐渐露出，远山保持在上三分之一”。只要求符合用户目标的约束，避免无关负面词堆叠。
5. **续接已有视频**：从接点附近选清晰原始帧，匹配画幅、主体位置和尺度、视角、运动方向与速度、色温和曝光。尾帧相同并不保证运动连续，需同时观察接点前后数帧。先判断能否直接接，必要时才用短叠化或其它符合意图的转场，不能靠转场掩盖明显内容错误。
6. **生成与验证**：遵循工具的费用与确认要求及用户已有授权。后台任务仍在进行时等待结果，不重复提交；失败后根据具体原因修正，避免无依据的付费重试。拿到成片后下载并按同样方法抽帧观看，核对动作、相机方向、主体一致性、时长、接点、闪烁和变形。涉及音乐、台词或音画同步时另外检查音轨。

最终交付可播放的视频 URL/文件，简要说明完成情况。只报告实际检查过的内容，未验证的声音、精确时点或运动必须注明；纯分析任务不触发视频生成。
