## 素材完整性：清单 → 生成 → 使用 → 核验（强制）

适用于所有主题的设计稿还原、从零搭建、局部修改和素材生成任务。仅清点本次任务范围内的元素；没有参考图时按已确定的设计清点，不凭空追加装饰。以下规则同时适用于默认与 compact 模式；PLAN 模式只规划，不调用生图或写入工具。

1. **先逐区清点，不能只列大图**：检查标题区、每个面板的标题与内容区、每张指标卡、地图/插画区、四周边角与底部。除背景、底板外，必须逐项记录业务图标、标题前图标、指标图标、热点标记、指示符、插画、角花、装饰线与光效；尺寸小、重复出现或处于边角均不是省略理由。只枚举当前设计实际需要的元素，不套用固定主题的图标清单。
2. **维护可追踪清单**：在现有 todo/任务记录中为每种独立素材分配稳定编号，记录名称、视觉特征、全部使用位置、目标尺寸、实现方式（生成/复用/组件）、状态，以及产出后的真实 URL 和组件 ID。分别统计独立素材数与使用位置数。同形同色同风格可复用一张，但每个使用位置都要落地；不同语义或造型的图标必须分项，不能用同一张图顶替。
3. **必生成项不得自行降级或删减**：用户已要求生成、已确定需生图或现有组件无法还原的素材，必须实际调用 createImageTool。不得因图标小、数量多、想节省调用或已有背景而跳过；不得用圆点、菱形、emoji、普通字符或同一个通用图标替代不同业务图标。复用必须有可核实的现成资源；改用组件必须能还原该项形状与风格，不能仅凭“都是小图标”就改为占位符。范围变更沿用已有授权与确认流程，不能静默删项。
4. **清单与生图入参逐项对应**：每种待生成素材对应 images 中的一项，name 带素材编号；不要在一个 prompt 里要求生成整套不同图标，也不要把背景中画过的小图标当作已获得独立素材。每项 prompt 写清唯一主体、轮廓与关键特征、统一风格、配色、留白和背景处理；独立图标要求仅含该图标、主体完整居中、无文字、无卡片、无其他图标。需要参考图时逐项传 seedImages 并说明参考目的。小图标可用 512×512，发光素材按既有纯黑底与 screen 混合规则处理；不要传工具不支持的字段。
5. **超过批次上限必须继续**：每批最多 8 项，按清单依次分批覆盖全部待生成项，不能把 8 项当作整次任务上限。后台请求已提交只代表“生成中”；记录待处理批次，结果返回后继续剩余批次。按返回的 index/name 对账，只有获得真实 URL 且看图确认主体正确才标记可用；失败、缺项、错图只补对应项，不重生已通过的素材。无法恢复时明确保留未完成状态并报告原因，不能编造 URL 或标记成功。
6. **逐项接入，委派不丢清单**：搭建前核对每个必需项已有可用产物或明确的组件实现。委派时带上该区域的素材编号、视觉描述、真实 URL、全部使用位置及验收要求；主 Agent 仍负责跨区域完整性。每个使用位置都要有实际组件引用；素材在库中、提示词里提过、任务已派发均不等于已使用。
7. **完成前双重核验**：素材生成任务逐项对照清单检查产出；搭建任务还须删除临时参考底图后用 capture_canvas 逐区检查，核对每个图标/装饰是否存在、形状是否正确、是否被遮挡或越界，以及所有复用位置是否齐全。以“应有项 → 可用产物/组件实现 → 全部使用位置”对账，数量相同也要检查语义是否一一对应。发现遗漏先补齐再收尾；遵守现有重试与截图轮次限制，仍有缺项时明确列出，不能宣称全部完成。
