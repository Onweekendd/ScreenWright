## 效果图 → 大屏工作流

用户提供整屏效果图，或 Agent 已按「大屏搭建工作流」生成整屏概念图后，按这条流程搭成能编辑、能接数据的大屏。概念图只负责设计参考，必须继续创建真实组件，不在出图后结束任务。

核心顺序：**先看清版面、列出要生成的素材，一次生成完，再组装**。不要边搭边生图，也不要生完图再回头猜它该放哪。

### 第 1 步：判断是「照搬版面」还是「重排版面」

- **照搬**：效果图和画布同比例（都是 16:9 的大屏稿），元素在哪画布上就在哪。建一个图片组件（swimg）铺满画布，
  url 用效果图的 url，命名「效果图底图」，放在最底层，后面用 `capture_canvas` 的 `snap: true` 在底图上量出每块区域的准确坐标——
  直接从效果图上目测坐标会差几十像素。全部搭完后删掉这张底图。
- **重排**：比例不同（竖版海报做成横版大屏），版面由你重新设计，位置和原图无关，不铺底图。

### 第 2 步：分清哪些是组件、哪些要生图

- **先逐区清点，再分类**（最容易漏的一步）：不要看到「背景、卡片底板」这几个大块就停。把效果图按区域过一遍——标题区、每张卡片（标题栏、内容区）、指标区、四周边角——每个区域把**所有非文字、非图表的视觉元素**逐个写下来：标题的书法字 / 印章 / 两侧装饰线、卡片标题前的小图标、卡片里的插画、指标旁的小图标、分割装饰、角花、光效点缀。这些「小模块」也要进清单，哪怕只有 64×64
- 清单每项写：在哪个区域、大致尺寸、和别处是否重复、归类（组件 / 生图）。写完回头数一遍，对照效果图逐区确认没漏
- **组件画得出来的才是组件**：文字、数字、图表、进度条、表格、分割线。记下文字原文、配色、数据含义，组装时照此配置
- **组件画不出来的要生图**：整屏背景、卡片底板、标题栏装饰、图标、插画、光效。长得一样的只生一张（六张卡片同一种底板 → 一张图、六个组件引用）；**长得不一样的各生各的**（三幅不同的民俗插画就是三张，不要用一张顶三张）
- 书法字、艺术字、印章这类带笔触和质感的标题，换成普通字体的文本框会明显变味：在清单里标出来，生成只含这几个字的图片（纯色底、不要别的元素）；用户要可编辑的文字时才改用组件，由用户在确认清单时决定
- 生图提示词只写这一张素材本身，写明「无文字、中间留空」（书法标题这类本身就是字的素材除外，写明是哪几个字、什么笔触）；边框类写「边框线紧贴画面四条边、四周不留空白」。同一批素材用同一段风格描述开头，风格才统一
- 深色底上的发光元素（光效、发光图标）生成时要求纯黑背景，组装时图片组件设 `mixBlendMode: "screen"`，黑底自动消失，不用抠图
- 很扁或很窄的条状素材（宽高比超过 4:1）生图会被拉变形，改用组件画

### 第 3 步：确认后生成素材

要生图时（要花钱、要等），先把清单整理给用户：每张的名称、用在哪、尺寸，**写明总数**，用 `ask_user_question` 确认。数量多、想省钱时，由用户决定砍哪几项，**不要自己悄悄省掉小元素**。
小图标、小插画 512×512 就够，不用 1920 起；一批最多 8 张，清单超过 8 项就分几批，每批一次调用，不要因为一批放不下就删小元素。
确认后用 `createImageTool` 生成：**这批素材一次调用，全放进 `images` 数组**（最多 8 张，每项各写 `name` / `prompt` / `width` / `height` / `seedImages`），不要拆成多次调用；服务端同时生成，6 张约 1~2 分钟。同一批里的图不能互相当参考图，要拿某张当参考就等它出来再调下一次。**不要传 `_background`**——传 `enabled:false` 会改成前台，卡住整轮对话。后台完成后结果（每张的 url、素材 id；失败的那张写明原因）会自动送回，不用为了拿 url 去开前台；只重试失败的那几张。`screenId` 填当前大屏。
生成的图会自动进用户素材库的「AI 生成」分组。逐张检查：风格是否统一、有没有生歪的（带了文字、不是要的东西、边框没贴边），
生歪的改提示词单独重做。

### 第 4 步：组装

- 素材 → 图片组件，位置尺寸照第 1 步量出的坐标，`objectFit: fill` 铺满
- 组件 → 按第 2 步记下的内容选组件、配内容和配色
- 卡片、标题栏这类容器，子组件建完后用 `group_component` 打成分组
- 组件多时按卡片拆成任务并发委派（见「大屏搭建工作流」Phase 3），委派 metadata 里带上概念图/效果图 URL、该卡片的坐标、内容、配色和素材 URL

### 第 5 步：截图对照

删掉第 1 步的效果图底图，`capture_canvas` 截整屏和效果图对照：布局、配色、文字、素材是否到位。**对着第 2 步的清单逐项勾**：每个区域的小图标、插画、装饰、书法标题是否都在，缺的补上，再说「完成」。
有出入按出入点改，对照最多两轮，剩下的差异如实告诉用户。

### 第 6 步（可选）：让背景动起来

只在用户想要动态背景、或者看完静态效果后主动提出时做，**不要自己加这一步**——视频一条要 1~3 分钟，还按秒计费。

- 用 `ask_user_question` 确认：用哪张图、动成什么样（流光、云层、粒子……）、几秒。通常 5 秒、720p 就够，只是看看效果用 480p
- 用 `createVideoTool` 生成：把整屏背景图的 url 放进 `firstFrameImage`，提示词**只写怎么动**（「光带缓缓流动，粒子轻微漂浮，镜头固定」），不要再描述画面，写明「循环感、无文字、无人物」。多条视频可以同时调用
- 首帧图的宽高比要接近画幅（0.4~2.5 以内）。很扁的横幅、很窄的竖条当不了首帧，会被直接拒绝；这种素材改用文生视频，或换一张图
- 用视频组件（`swvideo`）铺满画布放最底层，设成自动播放、循环、静音（浏览器只允许静音的视频自动播放）。字段名先用 `search_component` / `read_file` 看实际结构，不要凭印象填
- 你看不到视频的内容，生成后不要描述画面细节，告诉用户去预览里确认；前景文字压在动态背景上，用 `capture_canvas` 截图确认对比度还够
