## 效果图 → 大屏工作流（设计蓝图）

用户给了一张**整屏效果图**（设计稿、AI 生成的大屏效果图），要照着搭成能编辑、能接数据的大屏时走这条路。

核心顺序：**先定结构和素材清单，再批量准备素材，最后组装**。位置和层级在第一步就由你定好，
生图只按 key 出像素、不管放哪；不要边搭边生图，也不要生完图再回头猜它该放哪。

用到的三个工具在按需检索池里：先 `search_tools` 搜「设计蓝图 素材清单」，加载
`save_blueprint` / `read_blueprint` / `prepare_assets`。

### 第 0 步：把效果图铺到画布上当底图

建一个图片组件（swimg）铺满画布，url 用效果图的 url，命名「效果图底图」，放在最底层。
这样后面能用 `capture_canvas` 的 `snap: true` 在底图上量出每块区域的准确坐标——
直接从效果图上目测坐标会差几十像素。全部搭完后删掉这张底图。

### 第 1 步：写结构树和素材清单（`save_blueprint`）

**结构树**只拆到能定出素材清单的深度，一般两三层：大屏 → 卡片 / 标题栏 / 地图区 → 卡内元素。
图表怎么配、数字用多大字号留到组装时再定。

每个节点判断 `kind`：
- `group`：容器（卡片、标题栏），组装时建成分组
- `component`：文字、数字、图表、进度条、表格、分割线——**组件画得出来的一律是组件**，写上 `component`（组件类型）和 `note`（文字原文、配色、数据含义）
- `asset`：组件画不出来的图——背景、卡片底板、标题栏装饰、图标、插画、光效。引用素材清单里的 key

**素材清单**一项一张图，几处长得一样的只列一项（六张卡片同一种底板 → 一项素材、六个节点引用）。来源三选一：

| 来源 | 什么时候用 |
| --- | --- |
| `crop` 从效果图裁 | **首选**：最便宜、最还原。但裁的是这块区域里的**全部像素**——区域里叠着文字、数字、图表（之后要用组件重建）的就不能裁，否则组件和图上的旧字会叠出重影。适合图标、独立装饰、没有内容的背景区域 |
| `generate` 生图 | 要干净的底子时：卡片底板、标题栏、整屏背景（效果图上这些区域都压着内容）。prompt 只写这一项素材本身，写明「无文字、中间留空」；边框类写「边框线紧贴画面四条边、四周不留空白」。风格统一写在蓝图的 `style` 里，会自动拼到每张的 prompt 前面 |
| `reuse` 复用 | 素材库或之前生成过的图正好能用 |

- 深色底上的发光元素（光效、发光图标）裁下来设 `blend: "screen"`，组装时图片组件设 `mixBlendMode: "screen"`，黑底自动消失，不用抠图
- 很扁或很窄的条状素材（宽高比超过 4:1）生图会被拉变形：改成 `crop`，或者用组件画
- `palette` 填从效果图读出的主题色，组装时配色照它来

`region` 用画布坐标，用第 0 步的 snap 量；`z` 一般不填（默认面积大的在下、子节点在父节点之上）。
返回 `errors` 就按提示改完重新保存；`warnings` 逐条看，确实没问题再往下走。

### 第 2 步：跟用户确认素材清单

有 `generate` 素材时（要花钱、要等），把清单整理给用户：每项的名称、来源、用在哪、尺寸，
标明生图几张、裁切几张、复用几张，用 `ask_user_question` 确认。用户要删、要改成复用、要改风格的，改完重新 `save_blueprint` 再确认。
全是裁切 / 复用时不用问，直接下一步。

### 第 3 步：批量准备素材（`prepare_assets`）

不传 `keys`，一次把所有没就绪的素材都做了。它是后台工具，结果回来前可以先回复用户「素材准备中」。
结果后面跟着一张总览图（顺序见图片说明），检查：
- 风格是否统一、有没有生歪的（带了文字、不是要的东西、边框没贴边）→ 改那一项的 prompt，`save_blueprint` 后 `prepare_assets` 只传这几个 key 重做
- `failed` 的看 `error`：提示词超长就精简，服务报错就原样重试一次，还不行如实告诉用户

### 第 4 步：按结构树组装

先 `read_blueprint` 读回最新蓝图（素材的 `resultUrl` 在里面），节点已按「父在前、同级从下到上」排好：
- `asset` 节点 → 图片组件，url 用素材的 `resultUrl`，位置尺寸用节点 `region`、`objectFit: fill` 铺满；`blend: "screen"` 的设 `mixBlendMode: "screen"`
- `component` 节点 → 按 `component` 和 `note` 选组件、配内容，配色用 `palette`
- `group` 节点 → 子节点建完后用 `group_component` 打成分组
- 同级的叠放顺序照节点的 `z`（大的在上）

组件多时按卡片拆成任务并发委派（见「大屏搭建工作流」Phase 3），委派 metadata 里带上该卡片的节点和素材 url——子 agent 看不到蓝图。

### 第 5 步：截图对照

删掉第 0 步的效果图底图，`capture_canvas` 截整屏和效果图对照：布局、配色、文字、素材是否到位。
有出入按出入点改，对照最多两轮，剩下的差异如实告诉用户。
