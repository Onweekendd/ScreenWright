## 大屏搭建工作流

用户要求从零创建、重做整屏，或只有文字需求时，**先生成一张整屏概念图，再由 Agent 按图手动添加组件并完成大屏**。
用户已有整屏设计稿时直接按「效果图 → 大屏工作流」搭建；Figma 设计继续走 figmaToBIV2Workflow。
只有用户明确要应用已有模板时才走模板应用流程，不用套模板跳过从零建屏的概念图步骤。

**欢迎页示例范围**：`<welcome>` 任务先生成一张整屏概念图，再按图完成可编辑大屏。背景与装饰优先从概念图拆解或用组件还原；不主动搜索/导入联网素材或生成视频，不因主题联想到实拍、动态背景就追加这些任务。用户后续明确提出相关需求时再处理。概念图完成后继续施工，不能停在展示图片。

### Phase 1：生成整屏概念图

1. 从 editor-context 获取当前 screenId，读取 info.json 确认画布尺寸，结合需求确定业务主题、内容、布局、风格和配色。
   态势/监控大屏通常需要 12～18 项内容：指标逐个拆成单度量，补足趋势、排名、占比、列表和大屏标题；具体数量以需求为准。
   只对缺失且会改变结果的关键信息调用 ask_user_question，已有明确要求不要重复询问。
2. 调用 createImageTool 生成一张完整大屏概念图（`images` 里放一项）。screenId 用当前屏，name 标为「大屏概念图」，width/height 与画布一致。
   prompt 描述整屏：业务主题、标题与关键指标、各区内容与位置、图表形态、视觉层级、风格、配色及装饰。
   这是完整设计参考图，可以画文字和图表；不要套用素材图「无文字、中间留空」的提示词。
3. 等生成结果返回并查看概念图，记录返回的图片 URL 和版面、配色。生图失败先修正或如实报告，不跳过概念图直接堆组件。
   用户已要求从零建屏时，概念图属于这次任务；除非用户要求「先出图给我看」，不要出图后结束任务或额外等待一次开始指令。
   PLAN 模式下先提交计划，获批退出 PLAN 后再生图和施工。

### Phase 2：按概念图规划组件和素材

按「效果图 → 大屏工作流」看图定坐标、区分可编辑组件与图片素材，并准备需要的素材。

- 文字、数字、图表、表格必须创建为独立可编辑组件；概念图只当临时定位底图，不能贴一张整图就宣称完成。
- 背景、底板、装饰等素材按需生成或复用。需要与概念图保持构图或风格时，把概念图 URL 作为 createImageTool 里那几张图的 seedImages（每项各自的字段），并说明参考目的；这些素材一次调用放进同一个 `images` 数组。
- 记录各区坐标、尺寸、文字内容、配色、素材 URL、数据源和绑定关系。不要凭通用字段名猜组件专属配置，按需查该组件 schema。
- 没有真实数据源时准备与业务相符的演示数据并说明；有数据源时规划接入和必要的事件、过滤器验证。

小规模直接施工用 todoWrite 跟踪；多区域施工按卡片/区域划分任务：

1. 主 Agent 完成布局与内容规划，不把整体规划委派给施工 Agent。
2. 需要计划文件时用 create*plan / edit_plan 维护 screen*{screenId}/plan.json，PLAN 模式用 submit_plan 审批。
3. 每个区域先 create_task 建立 task_kind="create" 的 pending 任务，metadata 含 screenId、user_intent、skill_ref，
   并带上概念图 URL、该区域坐标、内容、配色及素材 URL；修改现有文件才用 task_kind="modify" 并提供已读取的文件上下文。
4. 用户已授权按概念图搭建时继续施工，不重复询问；确需选择方案时用 ask_user_question，PLAN 则等待计划获批。

### Phase 3：由 Agent 手动搭建

「手动」指 Agent 调用 createComponentTool / edit_files / group_component 等专用工具完成搭建，不是让用户自己去编辑器操作。

- 先创建可复用素材与独立组件，位置、尺寸、配色照概念图；多组件可用 components 数组批量创建。
- 卡片、标题栏这类容器按效果图流程分组，需要动态面板切换时完成状态与切换事件，不留下只有容器的空壳。
- 多区域任务按 sw-agent-core.md 的委派协议执行：任务 ID 分组互不重叠，并发最多 4，默认异步。
  发完说明已派发并等待后台报告注入，不轮询或重复委派；后台结果返回后继续剩余步骤直至完成。
- 数据接入遵循 BI 领域基本功，事件与过滤器配置完成后按要求验证，不把演示数据声称为真实接口取数。

### Phase 4：截图对照与收尾

- 处理每份 execution_report：失败时按原因补救，verification_required 时完成要求的校验，通过后再更新 completed。
- 删除临时概念图/效果图底图，保留正式使用的干净背景素材；文字、数字、图表应能独立编辑。
- capture_canvas 截整屏，对照概念图检查布局、配色、文字和素材，修复缺失、重叠、越界、明显空洞及未完成的面板切换。
  视觉对照最多两轮，仍有差异如实说明。
- 所有任务与必要验证完成后，再把计划标记 completed 并向用户报告结果；不能只生成概念图或派发任务就宣称大屏完成。
