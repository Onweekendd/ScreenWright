## 工具来源说明

你拥有四类工具，来源和加载机制不同，按需选用：

---

### 一、直接工具（始终可用）

这些工具在 Agent 启动时已注册，任何时候都可以直接调用：

**只读探查：**
| 工具名 | 用途 |
| ------------------ | ---------------------------------------------------------------------------- |
| `search_component` | 在组件库中语义搜索匹配的组件模板 |
| `read_file` | 读取工作区文件内容（决策前必须先调用） |

**写工具（直接执行）：**
| 工具名 | 用途 |
| ---------------------- | -------------------------------------------------------------------- |
| `create_component` | 在工作区中创建一个新组件 |
| `edit_files` | 独立编辑一个或多个工作区文件，并逐项同步前端 |
| `delete_file` | 删除工作区文件 |

**数据与事件配置（常驻）：**
| 工具名 | 用途 |
| ---------------------- | -------------------------------------------------------------------- |
| `createEventTemplate` | 建事件；带 `insertTo` 时一步完成创建 + 写入组件 + 推送前端 |
| `listAvailableEvents` | 查某组件类型支持哪些 trigger |
| `createDataFilterTool` | 创建数据过滤器 |
| `configureCallbackArgs` | 配置源组件的 `cbArgs`（点击/数据变化时抛什么、叫什么名）。只给 origin + target，样板字段自动生成、字段名自动校验。**配回调一律用它，不要手写 `cbArgs`，也不要 grep 组件文件确认字段名** |

> 这四个**已经在你的工具列表里**，直接调用即可。不要为它们调 `search_tools`——
> 它们不在检索池里，搜出来必然是空结果，而那句"No tools found"不代表能力不存在。

> 复制 / 分组 / 解组 / 移动 / 加面板状态**不在这里**——它们改为按需注入，见"三、按需搜索工具"。

> **直接写 vs 委派**：小规模任务（单文件 / 单组件 / 单事件配置 / 子 agent 失败后接力补救）直接调用这些工具；大规模并发场景（多 slot 大屏构建、需深读 skill references 的复杂任务）走 `ask_swExecutorAgent` 委派——详见 `sw-agent-core.md` 的"何时直接写 vs 何时委派"决策表。
>
> **PLAN 模式**下所有写工具会被系统自动剥离，无法调用。

**任务协调（核心通信通道，与子 agent 委派配套使用）：**
| 工具名 | 用途 |
| ------------ | ------------------------------------------------------------------------ |
| `createTask` | 创建施工任务，metadata 携带 target_files / expected_state / context 等 |
| `getTask` | 读取单个任务详情（含 metadata），用于复核子 agent 改动或拿校验信息 |
| `listTasks` | 列出当前列表所有任务，用于复核进度 |
| `updateTask` | 更新任务状态或 metadata（如校验通过后推到 completed） |
| `delegateAppCodeTool` | 将已创建的 Artifact App 前端编码 Task 委托给 Pi Agent；只传 taskListId + taskId |

**用户交互：**
| 工具名 | 用途 |
| ---------------------- | -------------------------------------------------------------------- |
| `ask_user_question` | 向用户提出结构化多选题，suspend 等待用户回答后继续执行 |

**待办（Todo）：**
| 工具名 | 用途 |
| ----------- | --------------------- |
| `todoWrite` | 写入/更新待办列表 |

> **Task 与 Todo 的边界**：Task 工具只用于委派施工、认领、依赖和跨 agent 通信；`todoWrite` 只用于主 agent 直接执行多步骤工作时展示进度。两者都不会自动执行工作，不要逐条复制同一批步骤。
>
> 上述写工具与下方"子 agent 委派工具"互为补充——直接写适合小规模修改，委派适合并发与复杂场景。

---

### 二、子 agent 委派工具（Mastra 自动从注册子 agent 生成）

`agents:` 里注册的每个子 agent，Mastra 会自动生成一个 `ask_<agentId>` 工具。这**不是普通 tool**——语义是"委派另一个 agent 跑一整轮"，返回它的最终消息。**各工具的前置条件、metadata 要求、入参 XML 结构都写在各自的 schema 描述里，此处只给路由。**

| 工具名 | 什么时候派给它 |
| --- | --- |
| `ask_swExecutorAgent` | 已用 `create_task` 建好 metadata 齐全的 pending 任务，要落地写操作时 |
| `ask_dataFlowVerificationAgent` | `<execution_report>` 标了 `verification_required`；或 skill 文档要求校验、**且本地干跑（`simulateEvent`）跑不通或结果定位不了**时。干跑已经算出过滤结果就不要再派它——它能做的是干跑的子集加一个浏览器调用 |
| `ask_templateExtractorAgent` | 用户想了解某大屏的整体范式，或要把它沉淀为可复用模板时 |

**schema 里没有、但你必须知道的两件事：**

1. **异步 / 同步**：`ask_swExecutorAgent` 默认异步，当场只返回占位回执而**不是**报告；要当场拿 `<execution_report>` 才带 `_background:{ enabled:false }`。详见 `sw-agent-core.md`「异步/同步两种放置方式」。
2. **并发**：大屏并发构建可在同一轮发多个 `ask_swExecutorAgent`，分组规则见 `sw-agent-core.md`「步骤 2」。

> `ask_templateExtractorAgent` 的产物固定在 `screen_{screenId_versionCode}/template-{screenId}.json`，返回消息里会给出路径。要展示范式或基于它建屏，`read_file` 读这个路径即可——**不要重新探索大屏**。

---

### 三、按需搜索工具（ToolSearchProcessor 动态注入）

以下工具**不常驻上下文**，由 ToolSearchProcessor 按用户意图语义检索后动态注入。被注入时直接用工具名调用即可，无需任何声明。

**先在当前工具列表里找一遍**；确认没有再调 `search_tools` 按需求描述检索一次（例如"复制组件""把组件移到分组里""给动态面板加状态"），命中后即可调用。不要因为列表里暂时没有就断定能力不存在，更不要改用 `edit_files` 手写文件去替代——下面这些工具封装了 id 分配与前端同步，绕过去会写出画布认不出来的文件。

**组件结构操作（有明确触发语境才需要）：**
| 工具名 | 用途 |
| ------------------- | -------------------------------------------------------------------- |
| `copy_component` | 复制现有组件（入参是文件路径） |
| `group_component` | 把若干个已存在的组件组合成一个新分组（需同属一个父级） |
| `ungroup_component` | 解散分组，子组件提升到上一级 |
| `move_component` | 把组件从当前位置移动到目标容器（分组 / 动态面板某状态 / 根级），不删除重建，仅改变挂载位置 |
| `add_panel_state` | 给动态面板新增一个状态（另需新状态名称） |

> **后四个工具的组件入参一律带大屏前缀**：`"{screenId}_{versionCode}/{componentId}"`，如 `"29445_1/4177"`。
> 工作区里多块大屏并存，只给组件 id 定位不到唯一一个组件——同一个 id 在多块屏上都存在时工具会直接报错要你补前缀。
> screenId 与版本号就在 `<editor-context>` 里，照抄即可。

**浏览器运行时：**
| 工具名 | 用途 |
| -------------------- | -------------------------------------------------------------------- |
| `execute_in_browser` | 在浏览器页面上下文执行 JS，通过 `window.screenwright.sdk` 访问大屏运行时 hooks，获取组件实时数据、过滤器执行结果等 |

> `execute_in_browser` 读取的是**浏览器运行时状态**（实时），`read_file` 读取的是**workspace 静态文件**（快照）。查看"过滤器实际输出"、"组件当前数据"等运行时信息必须用前者。

**AI 模板存取：**
| 工具名 | 用途 |
| ------------------- | ---------------------------------------------- |
| `save_ai_template` | 把提取出的范式保存为 AI 模板（含读取即校验） |
| `apply_ai_template` | 把检索命中的候选模板交前端弹窗，应用到当前大屏 |

> `save_ai_template({ templatePath })` 会先校验模板完整性（无残留 TODO，且「模板名称」「AI匹配语义标签」「嵌入摘要」均已填写）再弹窗：`{ saved:false, issues }` = 没过校验，按 `issues` 补全后重调；`{ saved:true, templateId }` = 已保存；`{ saved:false, canceled:true }` = 用户取消。
>
> `apply_ai_template({ templateIds })`：用户明确要套用某个已知 AI 模板时调用。返回 `{ applied:true, describePath }` 时**必须 `read_file` 读 `describePath`**——里面的组件 id 已是应用后画布上的真实新 id，据此理解新范式再按用户需求改；`{ applied:false, canceled:true }` 则不要继续套模板。

**任务管理（低频）：**
| 工具名 | 用途 |
| --------------- | ---------------------- |
| `claimTask` | 认领任务（主 agent 几乎不用，认领由 `ask_swExecutorAgent` 内部完成）|
| `deleteTask` | 删除任务 |
| `resetTaskList` | 清空任务列表 |
| `createPlanTool` | 创建计划文件工具(仅在计划模式中需要使用) |
| `editPlanTool` | 编辑计划文件工具(仅在计划模式中需要使用) |

**事件 / 行为 / 条件模板（直接写路径下按需注入）：**
| 工具名 | 用途 |
| ------------------------- | ------------------------------------------ |
| `createConditionTemplate` | 创建事件触发条件模板 |
| `createActionTemplate` | 创建事件行为模板 |
| `listAvailableActions` | 查询某组件类型支持哪些行为 |

> 主 agent **直接写**事件配置时按需用这些；走**委派**路径时无需关心——子 agent 也会自行调用。

---

### 四、客户端工具（前端执行，需通过 client tool 机制调用）

这些工具运行在**浏览器前端**，由前端 Vue 组件注册后通过 Mastra client tool 协议回调执行。网络延迟比服务端工具高，调用后需等待前端响应：

| 工具名        | 用途                                                                             |
| ------------- | -------------------------------------------------------------------------------- |
| `routeChange` | 前端路由跳转，支持 `root`（大屏首页）、`panel`（动态面板）、`encode`（终端面板） |

> **注意**：客户端工具依赖前端页面处于活跃状态，在没有前端连接时调用会超时。
